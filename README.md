# Queueing & Stochastic Fraud Detection

Comparing Hawkes processes vs. Markov-Modulated Poisson Processes (MMPP)
for detecting fraud bursts (e.g. card-testing attacks) in transaction
streams — with a queueing-theory layer modeling the payment gateway
itself, an LLM explanation layer (Cohere), and full pipeline tracing
(Langfuse).

Everything runs on synthetic data, CPU-only, on a laptop. No paid infra
required to reproduce.

## Why this project exists

Fraud detection portfolios usually stop at "train a classifier on
labeled transactions." This project looks one level deeper: the *arrival
pattern itself* — how fast transactions hit the gateway, and how that
clusters over time — is a fraud signal in its own right, independent of
any single transaction's features. Card-testing and account-takeover
attacks show up as bursty, self-exciting arrival patterns, which is
exactly what Hawkes processes and regime-switching Markov models are
built to describe.

Because the data is simulated, ground truth is known exactly — which
means the model comparison here is honest, not eyeballed.

## Architecture

```
arrival stream (Hawkes or MMPP generator, with labeled attack windows)
        │
        ▼
   queueing layer (SimPy M/M/c) ──► wait times / queue length
        │
        ▼
  detectors (fit Hawkes AND MMPP to the same stream)
        │
        ▼
  eval harness (precision/recall/F1, latency, AIC/BIC, fit time)
        │
        ▼
  Cohere: plain-language incident summaries for flagged windows
        │
        ▼
  Langfuse: traces every phase above
        │
        ▼
  Streamlit dashboard
```

## Quickstart

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

# optional — enables live LLM explanations / tracing; both degrade
# gracefully to no-ops without these set
export COHERE_API_KEY=...
export LANGFUSE_PUBLIC_KEY=...
export LANGFUSE_SECRET_KEY=...

streamlit run src/dashboard/app.py
```

Or explore the pieces directly:

```bash
python src/simulate/arrivals.py      # generators
python src/simulate/queue_model.py   # queueing layer
python src/detect/hawkes_fit.py      # Hawkes MLE fit + flagging
python src/detect/mmpp_fit.py        # MMPP/HMM fit + flagging
python src/eval/harness.py           # full comparison, both stream types
```

## Results (example run)

Cross-testing both detectors against both generator types shows each
model performs best on data generated by its own mechanism — the MMPP
detector is sharpest on regime-switching bursts (F1 ≈ 0.92 on MMPP data),
while Hawkes fares better, relatively, on self-exciting bursts. See
`src/eval/harness.py` output for exact numbers on your run/seed.

## Notes on parameters

Hawkes stability requires `alpha/beta < 1` (subcritical) even under the
attack-window multiplier, or the process explodes. See the comment in
`src/simulate/arrivals.py`.
